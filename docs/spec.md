# Carakan — web spec

Carakan is a mobile-first, installable, fully offline web app that teaches the Javanese script (aksara Jawa). It replaces the Flutter app `aksara-app` (ported from commit `ebc7cb5`, which stays unmodified). The old design spec is retired; this file is the current one.

## 1. Goal and users

- Goal: students open a link in the browser instead of installing an app. Full feature parity with the Flutter app at `ebc7cb5`, with a production-quality UI in the Buku Poster style ([`docs/decisions/0003-buku-poster.md`](decisions/0003-buku-poster.md)): ruled notebook paper, thick ink outlines, hard shadows, coral, periwinkle and butter accents, Bricolage Grotesque for the UI, Patrick Hand for hand notes, MPLUS Rounded 1c for transliteration and converter text, Jejeg for aksara.
- Primary users: elementary-school students (grade 3 and up) on cheap Android phones in Chrome. This is the design and acceptance target.
- Secondary users: teachers and adults who use the chart and converter, sometimes on tablet or desktop browsers. Layout works there; mobile comes first. From 48rem (768px) the app is an exercise book on a desk with index tabs on the page edge; activities become a worksheet (decision 0003).
- Not targets: iOS/Safari, a store package (see section 12).
- There is no backend. All content ships with the app. All learner state stays on the device. The app makes no request outside its own origin: no third-party fonts, CDNs, analytics or telemetry. No personal data is collected.

## 3. Engine

`src/engine/` is a pure TypeScript port of `packages/aksara_engine` at `ebc7cb5`, extended with a second ruleset. It carries two rulesets (`src/engine/ruleset.ts`): `pedoman-2002-v1` (`pedomanRulesetId`, the app default) and `kaj1-2021-simplified-v3` (`kajRulesetId`, the ported and frozen one). Each `Ruleset` also lists the murda, long swara forms, swara catalogue and rekan that the chart, picker and ladder teach. The Pedoman rules and their page cites are in [`docs/references/CITATIONS.md`](references/CITATIONS.md).

- API: `toAksara(latin, { useMurda, ruleset })` and `toLatin(aksara, { scheme: 'pujl' | 'jgst' })`. The engine default for `ruleset` is `kaj1-2021-simplified-v3`, because that is the ruleset the Dart differential freezes; the app passes the active ruleset at every call site. `toLatin` takes no ruleset: the Pedoman defines no transliteration and the reader already reads every Unicode form. Both return an explicit `success`, `ambiguous` (with candidates and a reason) or `error` (with `index` and `message`) result. Ambiguity is never resolved by a silent guess.
- Clusters: `toAksara` successes and ambiguous candidates also carry `clusters`, each with an `output` range and its `sources` (UTF-16 ranges of the given input). The output string is unchanged. Clusters break at letters, digits and pada, except a letter after pangkon (pasangan); a ZWNJ belongs to the cluster it closes. `tests/engine/clusters.test.ts` checks this.
- Pipeline (Latin → aksara): syllabify, map each syllable to a base aksara plus sandhangan, resolve consonant clusters into pasangan, apply pada and punctuation, join words. In joined writing the two rulesets differ at word joins: under KAJ a comma after a pangkon is that pangkon plus a zero-width non-joiner, a full stop after a pangkon is pada lingsa, and a pangkon-final word links as pasangan to any next word. Under the Pedoman a full stop is always pada lungsi, and a pangkon-final word keeps a visible pangkon (a ZWNJ) before a word that starts with a swara letter or a consonant cluster. Aksara → Latin is nearly mechanical. Taling is stored after its base (Unicode logical order).
- Pedoman 2002 differences (each cited in CITATIONS): 7 murda, murda only on the first aksara of a word (opt-in `useMurda` follows this); no long-vowel or diphthong signs (`ii`, `uu`, long swara A are errors); `ai` and `au` are two aksara and so ambiguous (ha reading first, swara reading second, never picked); a swara letter is never a pasangan; no three-tier stacks; fa and va are one letter (PA + cecak telu, read back as `f`). Where the Pedoman is silent the engine keeps KAJ I v3.
- Codepoints are generated by `tools/gen-codepoints.ts` (`npm run gen:codepoints`) from the archived Unicode slice `docs/references/unicode-javanese-block.txt` into `src/engine/codepoints.ts`. They are never hand-typed. No aksara literal appears in source, tests or tools; a guard test enforces it.
- Purity: `src/engine/**` imports only engine modules and is compiled under `src/engine/tsconfig.json` with no DOM and no Node types, so a DOM or Node reference is a type error. `tests/engine/engine-purity.test.ts` guards the import rule.
- Differential provenance: `tests/engine/fixtures/dart-ebc7cb5.json` is the Dart engine's output at `ebc7cb5` over the golden pairs, the full corpus, the shaping cases and a planner-defined input set, in both directions and both schemes, with `useMurda` on and off. `npm run parity:dump` regenerates it from the Dart source (extracted with `git archive`; the source repository is never touched). `tests/engine/differential.test.ts` asserts zero differences. It is a KAJ I gate only (the Dart engine has no Pedoman mode). The Pedoman's oracle is the page-cited golden list `tests/engine/pedoman-2002-cases.ts`, run by `tests/engine/pedoman-2002.test.ts`.
- Approved deviation from Dart (contract section 3.1, implemented in Task 04b): the Dart engine throws an unhandled exception when a cluster marker (cakra `ŕ`, pengkal `ỿ` or keret/pa-cerek `ṛ`) stands where a syllable-closing consonant would go (`kaŕ`, `raỿ`, `kaṛ`). The TypeScript engine returns an `error` result for those inputs. No input that the Dart engine converts changes its result. `toAksara` and `toLatin` never throw; `tests/engine/no-throw.test.ts` runs a seeded fuzz check and the differential test allowlists exactly the Dart-throwing records.
- Messages: the engine keeps English messages. The app localizes them through `src/features/converter/engine-messages.ts` (W15): every engine message, including the parameterized `Unknown character "<c>"` and `Unrecognized codepoint U+<hex>`, maps to an `engine*` message key in both locales; an unmapped message shows `engineErrorGeneric`. A source scan of `src/engine/**` fails `npm test` when an engine message has no mapping.

## 4. Content

Content `v1` is carried over byte for byte in `public/content/v1/`, except `units.json`, `words.json` and `manifest.json` (teacher feedback round 2 regrouped the base-letter units by shape and added `retiredUnits`; the Pedoman ruleset added `byRuleset`, the unit `rulesets` key and `manifest.rulesetIds`): `aksara.json`, `sandhangan.json`, `words.json`, `units.json`, `confusion_pairs.json`, `chart_examples.json`, `manifest.json`.

- Unit ids name a fixed glyph set and are never reused. A regroup gives the changed units new ids and lists the old ones in `retiredUnits`. Units whose glyphs did not change keep their ids (`u2`, `u6`, `u7`, `u8`; the groups are `g1`–`g5`). A unit may carry `rulesets`, the rulesets whose ladder has it (absent means every ruleset). The eighth unit differs by ruleset, so it is two units: `u8` (18 glyphs, `kaj1-2021-simplified-v3`) and `u8p` (14 glyphs: 7 murda, a i u e o, pa cerek, nga lelet; `pedoman-2002-v1`).
- Content stays `v1` with `contentVersion` 1: nothing reads the version; the service worker precaches each JSON file by revision, so the new `units.json` arrives with the code that reads it; the added key is ignored by older code.
- Gates: `tests/content/units.test.ts` pins the order, checks that every glyph of the active ruleset is taught exactly once, and checks the retired units.
- The aksara and sandhangan catalogs are derived from the engine by `tools/gen-content.ts` (`npm run gen:content`) and regenerate byte for byte (`tests/tools/gen-content.test.ts`).
- Content is fetched once at bootstrap by `readContent` (`src/content/content-repository.ts`); `contentFor` builds the view for each ruleset from that one source. It has real loading and error-with-retry states.
- Gates (`tests/content/**`, run by `npm test`, under both rulesets): every corpus word round-trips through the engine (the Pedoman read-back of `vila` and `vakum` as `fila` and `fakum/` is the documented exception); the manifest ruleset ids and the murda Latin fields match the engine; chart examples have no pasangan and show the glyph they are listed under; units, confusion pairs, school spelling, glyph derivation and glyph universe checks.
- Invariant: the wordlist never stores aksara. It stores canonical JGST Latin only and renders through the engine.
- Corpus rules and how to add words: [`docs/content/corpus-guide.md`](content/corpus-guide.md). Word licensing: [`docs/references/wordlist-licensing.md`](references/wordlist-licensing.md).
- Content strings (unit names, glyph names, glosses) and the feedback report stay Indonesian under the English UI.
- Per-ruleset words: an entry in `words.json` may carry `byRuleset`, a map from a ruleset id to overrides (`canonical`, `displayPujl`, `requiredGlyphs`, `requiredCaps`). Top-level fields apply to every ruleset without an override. Under the Pedoman: `nabi` is `ṇabi`, `ramai` is stored `ramahi` and shown `ramai` (provisional), and `vila` and `vakum` need glyph `fa` instead of `va`. `manifest.json` lists `rulesetIds`. `contentFor(source, rulesetId)` returns the content for one ruleset; chart examples keep only keys whose glyph the ruleset has. The glyph universe stays 57 ids; the Pedoman set is 47.

## 5. Architecture

- Stack: Vite, Svelte 5, TypeScript, client-only. No Tailwind: `src/styles/tokens.css` mirrors the Buku Poster tokens (`docs/design/buku-poster/tokens.json`) and is the only place that holds colour or size literals. npm with a lockfile, Prettier, Vitest, Playwright.
- Layout: `src/engine/` (pure), `src/content/` (models, loader, glyph table), `src/core/` (`db/`, `srs/`, `locale/`, `app-info.ts`), `src/l10n/`, `src/app/` (shell, router, services, bootstrap), `src/ui/` (design system, Lucide icon data in `icons.ts`), `src/styles/`, `src/features/{lessons,chart,review,converter,settings}/`. Tests live in `tests/{engine,content,unit,tools,e2e}/`; build, audit and generation scripts in `tools/`.
- State pattern: feature logic is framework-free TypeScript exposing `svelte/store` readables and async methods; components subscribe. Time is injected as `now()` and randomness as `seedSource()`, so logic is deterministic under test.
- Services and sessions: `bootstrap.ts` builds one `Services` container for the shared storage and runtime (IndexedDB repositories, `LearnerProgress`, `ReviewQueue`, content, glyph table, locale controller, i18n, `activeTab`) and `App.svelte` provides it through context. `LadderModel`, `ReviewSession` and `DrillSession` are created through `singleton`, so they live for the lifetime of their ruleset scope (see Ruleset scopes) and the review retry set survives tab switches. They also subscribe to `LearnerProgress.erased`, so an erase shows the fresh ladder, an empty review list and no drill without a reload; the review session drops its retry set in its own promise chain.
- Ruleset scopes: `RulesetController` (`src/core/ruleset/ruleset-controller.ts`) holds the writing-ruleset choice in `localStorage['carakan.ruleset']` (`pedoman-2002-v1` or `kaj1-2021-simplified-v3`). No value, an unknown value or an unreadable store means `pedoman-2002-v1`. `select` persists first and applies only if the write succeeded. `Services.forRuleset(id)` returns one memoized scope per ruleset: that ruleset's `content` and `glyphInfo` and its own `singleton` registry, over the shared storage and runtime. `AppReady.svelte` wraps the shell and every pushed page except Settings in `{#key $active}` with `RulesetScope.svelte`, so a switch remounts them under the new scope without a reload: converter input and open sheets reset, Settings stays mounted. Progress is shared and nothing is erased: a ladder counts a unit as complete when all its glyphs were completed in either ruleset (it maps completions of the other ruleset's units by glyphs, through `unitsCompletedByRetired`), and Ulangi hides the cards for glyphs the active ruleset lacks while keeping them stored.
- Routing: hash routing in `src/app/router.ts`, no dependency, no server rewrites. Tab switches use `history.replaceState`; pushed routes use `history.pushState({ carakan: depth })`. `back()` is `history.back()` when the stored depth is above 0, else a replace to `#/`.
- Keep-alive shell: `AppShell.svelte` mounts all four tab pages once and hides the inactive ones, so converter input and chart scroll survive switching. Pushed pages render above the hidden shell.
- Storage: IndexedDB database `carakan`, version 1, through `idb`. Object stores: `srsItems` (key `itemId`, index `dueAt`), `unitCompletions` (key `unitId`), `mistakeLogs` (key `confusionPair`). Times are epoch milliseconds. Schema constants are exported from `src/core/db/schema.ts`. Completions under a retired unit id stay stored. On each refresh the ladder marks a current unit completed when every glyph of it was in a completed retired unit (`unitsCompletedByRetired`), writing those completions once with `completeAll`. The database stays at version 1: a version bump would block behind an old-build window during an update. The language choice is in `localStorage['carakan.uiLocale']` (`system`, `id` or `en`). The Settings erase (`LearnerProgress.erase`, `src/core/db/learner-progress.ts`) clears `srsItems`, `unitCompletions` (retired-unit records included) and `mistakeLogs` in one readwrite transaction and emits `erased` only after it commits. On a failure it aborts the transaction, so nothing changes, and the dialog shows `resetFailed`. It never touches `localStorage` or the service-worker cache, and the database stays at version 1. A storage failure after boot never leaves a stuck screen: the ladder, the lesson load, the review list and the drill show `storageErrorTitle` with `retryButton`; a failed lesson step keeps its question and offers the same retry; a drill answer that could not be stored stays open for another tap; a connection the browser closes (`terminated`) boots the app again, which reopens it or shows the boot storage error.
- SRS: `src/core/srs/srs-scheduler.ts` is pure. New item due now, ease 2.5. Again: due in 10 minutes, ease −0.2. Hard: due in `max(interval, 1)` days, ease −0.15. Good: interval 1 on the first repetition, else `round(interval × ease)`. Easy: interval 6 on the first repetition, else `round(interval × ease × 1.3)`, ease +0.15. Ease is clamped to [1.3, 3.0].
- l10n: `src/l10n/id.json` and `en.json`, flat keys with `{name}` placeholders. Indonesian is primary and the fallback; System follows the browser language list (first of `id`/`en`, else Indonesian). `<html lang>` follows the resolved locale. Tests require identical key and placeholder sets and fail on hard-coded UI strings.
- Sound: `public/audio/clips.json` maps a reading to a clip path; `ClipPlayer` (`src/core/audio/`) plays it, and a missing clip or failed load shows an "audio is coming soon" toast. The manifest is empty because no recordings exist yet. Not ported: dependency injection and drift code generation (replaced by the structure above).

## 6. Offline and PWA

- `vite-plugin-pwa` (`generateSW`, `registerType: 'prompt'`) precaches every file in `dist` (html, js, css, json, woff2, ttf, png, svg, webmanifest, txt): shell, content, fonts and `audio/clips.json`. After the first load every surface works with no network. The manifest (`id`, `start_url`, `scope` all `/`) and icons make the app installable on Android Chrome. Clip files themselves (`ogg`, `opus`, `mp3`, `m4a`, `wav`) are not in these patterns: add them when the first clip ships.
- Update policy: a new service worker waits. It activates on the next launch (all clients closed) or when the user accepts the update banner. The banner never shows on `#/lesson/*`, `#/trace/*` or `#/review/quiz`, and only the window whose Reload button was tapped reloads (`onNeedReload` in `UpdateBanner.svelte`; the library default reloads every window). Another window keeps running on its loaded assets: the only lazy chunk (workbox-window) loads at startup before any takeover, and gets the new build on its next load or its own Reload, so an update never interrupts a lesson or review.
- Persistence: the app requests `navigator.storage.persist()` at startup when storage is not yet persistent.
- Risk: learner state lives only in browser storage. Clearing site data erases progress. There is no export or import (deferred, section 12).

## 7. Fonts

- MPLUS Rounded 1c is subset to the glyphs the app needs: Latin, Indonesian and every JGST diacritic the engine can output. `tools/fonts/glyphset.ts` derives the glyph set (`fonts/glyphset.txt`) from the UI strings and the engine; `tools/fonts/subset.sh` (`npm run fonts`) subsets the carried TTFs in `fonts/source/` to `public/fonts/mplus-rounded-1c-{400,700}.woff2` and `tools/fonts/check_coverage.py` fails when a glyph-set code point is missing. Any task that changes a UI string reruns `npm run fonts`; a drift test fails until the regenerated files are committed. The echoed character of `Unknown character "…"` messages is not in the glyph set, so typed characters fall back to the system font.
- Bricolage Grotesque (500, 700, 800) and Patrick Hand (400) ship as unmodified fontsource WOFF2 files (latin and latin-ext subsets) in `public/fonts/`, under the SIL Open Font License (`public/licenses/ofl-bricolage-grotesque.txt`, `ofl-patrick-hand.txt`). Bricolage is the UI face; Patrick Hand is for notes, hints and stamps.
- Reading font rule (D3 refinement): a Latin reading shown on its own (glyph readings, entry names, unit titles, answer options, breakdown names) renders whole in Bricolage when every code point is in the bundled Bricolage subsets, else whole in MPLUS; never mixed in one string. Converter input, output and echo stay MPLUS. The coverage is generated from the WOFF2 cmaps by `tools/fonts/display_coverage.py` into `src/ui/display-coverage.ts` (never hand-edited), run by `npm run fonts`.
- Jejeg (`nykNgayogyanJejeg-Regular.ttf`) is served unmodified: no subsetting and no re-encoding, so the app does not ship a derived work of an all-rights-reserved font. It is declared with `unicode-range: U+A980-A9DF, U+200C-200D, U+25CC`. Aksara text uses `"MPLUS Rounded 1c", "Jejeg", sans-serif`, MPLUS first, so Latin never uses Jejeg's Latin.
- Shaping is checked against the exact shipped Jejeg bytes: `npm run shaping` compares the TypeScript engine's case dump with the Dart dump byte for byte, shapes every case with HarfBuzz (`# 0 failing case(s)`), and checks that no HarfBuzz cluster straddles an engine cluster boundary.
- Rendering: the converter result stays one text node. Tap targets and the selection mark are an overlay measured with `Range` rects. Reason: in Chrome, splitting the text into elements with an absolute `::after` or `inline-block` drops Jejeg's cross-cluster positioning after a panjing la.
- Licensing status: no license text ships with Jejeg. The maintainer accepted deploying it while the rights holder's written permission is pending; this is recorded in `public/licenses/NOTICE-fonts.txt`. Record the permission there when it arrives.

## 9. Hosting

- Target: `https://carakan.fiatcode.dev/`, served from the domain root. There is no demo deploy. Hash routing keeps every route at `/`, so no server rewrites exist anywhere.
- Image: the `Dockerfile` builds with `node:24-alpine` (`CARAKAN_BUILD_ID` build arg required; it becomes `meta[name=carakan-build]`) and serves `dist` with `static-web-server:2-alpine` and `sws.config.toml`. This follows the `site/` convention.
- Cache policy (`sws.config.toml`): `**` gets `no-cache`; `/assets/**` (Vite's content-hashed output) gets `public, max-age=31536000, immutable`. HTML, `sw.js`, `workbox-*.js`, the manifest and every unhashed file (content JSON, fonts, icons, licenses) must revalidate: the service worker's install and update fetches must never be answered from a stale HTTP cache, or an update would never arrive (contract risk, section 8). Compression is on.
- CI: `.github/workflows/ci.yml` (`lint-and-test`) runs `format:check`, `check`, the root `tsc` and the Vitest suite on every pull request and on every push to `main`. `.github/workflows/build.yml` (`build`) builds the image on pull requests and, on push to `main`, pushes `ghcr.io/fiatcode-gh/carakan:{latest,<sha>}`. The `main` ruleset requires both checks.
- Production routing: a `carakan.container` quadlet unit and a Traefik router with a TLS certificate live in `fiatcode-infra`, not in this repository.
- Production runbook: [`docs/deploy.md`](deploy.md) covers the release path from the full gate to the image, the server rollout, the post-publish checks and rollback.
- Local proof: `npm run served:up` builds the production image and runs it behind a Traefik configured like production at `http://localhost:8090/`. `served:headers` checks content types, cache headers, compression and no SPA rewrite. HSTS is asserted only for https base URLs, because Traefik sets it only over TLS; production proof of HSTS and the certificate belongs to the production acceptance (Task 21).

## 11. Rule authority

The engine carries two rulesets and the user chooses one in Settings; the default is Pedoman 2002 (`pedoman-2002-v1`). The other is Kongres Aksara Jawa I, Yogyakarta 2021, Simplified style (`kaj1-2021-simplified-v3`), unchanged. Pedoman 2002 is _Pedoman Penulisan Aksara Jawa_ (Yayasan Pustaka Nusatama, 2002), the school standard; where it is silent the engine keeps KAJ I behaviour. JGST (KAJ I Komisi I) is the canonical scheme and PUJL (school spelling) is the user-facing one under both. Murda is never applied by the converter unless opted in. Sources, page cites per Pedoman rule, the points where the Pedoman is silent, version history (v1 → v2 → v3) and the rationale for each rule are in [`docs/references/CITATIONS.md`](references/CITATIONS.md); the KAJ I PDF and the Unicode Javanese block slice are alongside it (the Pedoman PDF is not in the repository). The active ruleset id and its sources are shown in About and in the feedback report. The open Pedoman questions for the teacher are in [`docs/content/teacher-review-pedoman-2002.md`](content/teacher-review-pedoman-2002.md); the decision record is [`docs/decisions/0002-pedoman-2002-ruleset.md`](decisions/0002-pedoman-2002-ruleset.md).
