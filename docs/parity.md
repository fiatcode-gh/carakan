# Carakan web port — parity checklist

Parity authority for contract §3.3 (`.flow/contracts/carakan-web-port.md`). Derived from the Flutter source at
`aksara-app@ebc7cb524ca7ddea8a3adca8b21939cd3da09bca` (`app/lib/**`, `app/lib/l10n/*.arb`, `app/assets/content/v1/*`,
`packages/aksara_engine/**`). Where this list and the source disagree, the source wins unless the item is changed by an
approved rework decision (section W below, recorded in `docs/decisions/0001-ui-rework.md`). This tracked file is the parity
authority; `docs/spec.md` links it.

## How proof works

- Every item has an ID. Every automated proof names that ID in its test title, e.g. `test('[P-B07] meet phase shows …')`.
- `npm run parity:coverage` (`tools/parity-coverage.ts`) fails unless every ID whose proof column says `e2e` or `unit` appears in at least one
  test title (Vitest or Playwright project `mobile`). The full gate runs `npm test` and `npm run test:e2e` on the same tree.
- The Task column names the plan task that implemented the item; it is history, not a requirement.
- `e2e` = Playwright, Chromium, project `mobile` (360×740, touch, `locale: id-ID` unless the item says otherwise).
- `unit` = Vitest (`tests/**`). `gate` = a named script/command. `device` = Task 19/21 phone evidence.
- Item text uses message keys (`navLadder`) instead of copy; copy lives in `src/l10n/{id,en}.json`.

- `AudioService` and `audioKey` playback: no recordings exist and no UI ever called it (contract §9). `audioKey` fields stay in the JSON untouched.
